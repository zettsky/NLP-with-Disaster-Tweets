        How it works

        1. Upload a Kaggle-style CSV (id, keyword, location, text[, target]) or a TXT file with one tweet per line.
        2. Tokenise each tweet into words. Each known word carries a fixed weight: positive pushes the score toward “disaster”, negative pushes it toward “not”.
        3. Score the tweet: add up bias + Σ weights, then squash it through a sigmoid so it reads as a probability p between 0 and 1.
        4. Sort into three pages by p: real disaster (≥ 0.65), uncertain (0.35–0.65), not a disaster (≤ 0.35). In each tweet, underlined words pushed the score up; struck-through words pulled it down.

        The formula

        p(disaster) = 1 / (1 + e^-(bias + Σ word_weight))

        Example — “Wildfire near the highway forces evacuation”: wildfire +2.8, evacuation +2.4, bias −0.5 → score 4.7 → p ≈ 0.99, sorted into Real disaster.

        Reading the cards

        underlined = pushed toward disaster struck = pushed toward not ■■■■□□□□□□ = the probability meter, 1 block per 10%

        wildfire / tsunami+2.8

        lol / lmao−2.0
        mixtape−2.0
        cute−1.6
        birthday / pizza−1.6

        Unseen words score 0. A small per-tweet jitter keeps otherwise neutral tweets from all landing on exactly 50%, so the “uncertain” pile isn't empty.

        The dataset

        “Load train.csv” runs the labelled training set from Kaggle's Natural Language Processing with Disaster Tweets competition through this pseudo model, so you can see the pipeline work on real tweets before any real model exists.

        7,613 labelled tweets 3,271 real disaster (43%) 4,342 not a disaster (57%) 7,552 tagged with a keyword 5,079 tagged with a location

        The competition itself is scored on F1, not raw accuracy — this UI shows accuracy on the tweets the pseudo model is confident about (outside the uncertain band) since it has no real precision/recall to speak of yet.

        About the “Search on X” links

        The dataset's id column is just a row number, not a real tweet ID, so there's no reliable link back to the original tweet. Each card instead links to an X search for its own text, as the closest honest substitute.

        This is a placeholder model, built to get the interface right before the real one exists. Swap model.js → predict() for a trained classifier later — the UI, animation and dataset loading all stay the same.
